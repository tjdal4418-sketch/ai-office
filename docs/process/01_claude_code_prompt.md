# AI 오피스 — 클로드코드 프롬프트

> 사용법
> 1. 빈 폴더(예: `C:\path\to\ai-office`)에서 클로드코드를 실행합니다.
> 2. **[0] 마스터 프롬프트**를 먼저 붙여넣어 프로젝트 전체 설계와 `CLAUDE.md`를 만들게 합니다.
> 3. 이후 **[1]~[6] 단계 프롬프트**를 하나씩 붙여넣고, 단계마다 실행·확인한 뒤 다음으로 넘어갑니다.
> (한 번에 전부 시키면 코드가 엉키기 쉬워서 단계로 나눴습니다.)

## [0] 마스터 프롬프트 (가장 먼저 붙여넣기)

```
너는 회계·세무 도메인을 이해하는 풀스택 개발자야. 지금부터 "AI 오피스"라는 웹앱을 함께 만들 거야.
이 프로젝트는 EY한영 통합세무팀(아웃소싱 회계·세무 서비스) 지원용 포트폴리오이고, GitHub에 공개할 예정이야.

## 1. 프로젝트 개념
- 가상의 회계법인 사무실에 "AI 직원(에이전트)" 5명이 근무한다.
- 각 에이전트는 통합세무팀의 실제 담당업무 하나씩을 맡아 반복 업무를 자동화한다.
- 홈페이지(대시보드)에서 사무실 평면도처럼 각 에이전트의 자리와 현재 상태(일하는중/대기중 등)를 실시간으로 보여준다.
- 핵심 원칙: AI는 "작성·검증·대사"까지만 하고, 최종 확정은 사람(담당자)이 "검토 승인"한다. (Human-in-the-loop)

## 2. 에이전트 구성 (담당업무 = 채용공고 기준)
| 에이전트 | 담당 | 주요 자동화 |
|---|---|---|
| 페이 (Payroll) | Payroll & Withholding Tax | 급여 계산, 4대보험, 근로/사업/기타소득 원천세, 원천징수이행상황신고서 집계 |
| 북키 (BK) | Bookkeeping & Accounting | 거래내역 → 분개 추천, 시산표, 계정 Reconciliation, 결산 체크리스트, 감사 PBC 리스트 |
| 배트 (VAT) | VAT & Tax Compliance | 세금계산서 vs 장부 대사, 불공제 매입세액 플래그, 부가세 신고서 요약 |
| 코택 (Corp Tax) | Corporate Tax & Other Tax | 법인세 세무조정 체크리스트, 접대비 한도 계산, 세무조사 대응 자료 목록 |
| 매니저 (Office Manager) | 총괄 | 업무 배분, 신고기한 캘린더, 전체 진행 현황 리포트 |
(이름은 바꿔도 됨. 캐릭터 이모지/아이콘을 하나씩 정해줘.)

## 3. 에이전트 상태값 (홈페이지에 표시)
- 🟢 대기중(idle): 할 일 없음
- 🔵 일하는중(working): 작업 처리 중, 진행률(%)과 현재 단계 텍스트 표시 (예: "급여대장 32명 중 18명 계산 중")
- 🟡 검토필요(review): 작업 완료, 사람의 승인 대기
- ✅ 완료(done): 승인 완료 (일정 시간 뒤 자동으로 대기중 복귀)
- 🔴 오류(error): 데이터 오류 발견, 사유 표시 (예: "주민번호 누락 2건")

## 4. 기술 스택 (변경 제안 있으면 이유와 함께 먼저 말해줘)
- 백엔드: Python 3.11+, FastAPI, pandas, openpyxl, SQLite(SQLAlchemy)
- 작업 처리: FastAPI BackgroundTasks 또는 asyncio 큐 (외부 인프라 없이 로컬에서 바로 실행 가능해야 함)
- 실시간 상태: Server-Sent Events(SSE) 우선, 어려우면 2초 폴링
- 프론트엔드: 단일 페이지 HTML + Tailwind CDN + 바닐라 JS (빌드 도구 없이 실행)
- 결과물: 엑셀(.xlsx) 다운로드 — 계산 셀은 가능한 한 엑셀 수식이 살아있게 작성
- 실행: `pip install -r requirements.txt` → `uvicorn app.main:app --reload` 한 줄로 실행

## 5. 폴더 구조 (초안)
ai-office/
├─ app/
│  ├─ main.py              # FastAPI 진입점, 라우터 등록
│  ├─ core/                # 상태관리(state.py), 작업큐(queue.py), SSE(events.py), DB
│  ├─ agents/              # base.py(공통 클래스) + payroll.py, bookkeeping.py, vat.py, corptax.py, manager.py
│  ├─ rules/               # 세율·요율·기한 등 "법령 기반 수치" (YAML/CSV) — 코드에 하드코딩 금지
│  └─ static/              # index.html(홈), agent.html(상세), css/js
├─ sample_data/            # 가상 고객사 샘플 엑셀/CSV
├─ outputs/                # 생성된 결과 파일
├─ tests/                  # pytest
├─ CLAUDE.md
└─ README.md

## 6. 반드시 지킬 규칙
1. 세율·보험요율·간이세액표·신고기한 같은 수치는 전부 app/rules/ 의 설정 파일에 두고, 각 항목에 "근거 법령/고시명, 적용연도, 확인일"을 주석으로 남겨라.
   네가 모르거나 최신 여부가 불확실한 수치는 추측하지 말고 `# TODO: 확인 필요`로 표시하고 나에게 목록으로 알려줘. (내가 법령 MCP로 검증할 거야)
2. 샘플 데이터는 전부 가상 회사·가상 인물로 만든다. 실제 주민번호 형식의 값은 마스킹(예: 900101-1******).
3. 모든 에이전트는 공통 BaseAgent를 상속하고, 상태 변경은 반드시 공통 함수(set_status)로만 한다 → 홈페이지에 자동 반영.
4. 각 작업은 "입력 검증 → 계산/대사 → 이상항목 리포트 → 결과파일 생성 → 검토필요" 순서를 따른다.
5. 계산 로직마다 pytest 단위테스트를 작성하고, 손계산 가능한 예시(예: 월급 300만원 1명)로 검증한다.
6. 코드 주석과 UI 문구는 한국어, 변수명은 영어.
7. 단계별로 진행한다. 한 단계가 끝나면 "실행 방법 / 확인할 화면 / 다음 단계"를 요약하고 멈춰라.

## [1] 단계 1 — 상태 시스템 + AI 오피스 홈페이지

```
CLAUDE.md를 읽고 1단계를 진행해줘: 에이전트 상태 시스템과 홈페이지.

[백엔드]
- app/core/state.py: 에이전트별 상태(status, progress, current_step, client_name, updated_at, last_message) 관리
- app/agents/base.py: BaseAgent 클래스 — set_status(), log(), run() 추상메서드
- 상태 변경 시 SSE(/api/events)로 프론트에 즉시 푸시
- 작업 이력(누가, 어느 고객사, 무슨 작업, 시작/종료, 결과)을 SQLite에 저장
- API: GET /api/agents, GET /api/agents/{id}, GET /api/activity, POST /api/agents/{id}/approve
- 테스트용 "데모 작업"(10초 동안 진행률 0→100%, 마지막에 검토필요)을 각 에이전트에 붙여줘

[홈페이지 index.html]
- 상단: "AI 오피스" 로고, 오늘 날짜, 다가오는 신고기한 D-day 배지 3개
- 가운데: 사무실 평면도 — 5개 책상 카드(캐릭터, 이름, 담당업무, 상태 배지)
  · 대기중: 캐릭터가 천천히 숨쉬는 애니메이션, 회색 톤
  · 일하는중: 키보드 치는 애니메이션 + 진행률 바 + 현재 단계 문구
  · 검토필요: 노란 깜빡임 + "검토하기" 버튼
  · 오류: 빨간 테두리 + 오류 사유
- 우측: 실시간 활동 로그 피드 ("14:02 페이 — (주)가나상사 10월 급여 계산 시작")
- 하단: 오늘 처리 건수 / 검토 대기 건수 / 오류 건수 요약 카드
- 반응형(모바일에서 카드 세로 배치), 다크모드 지원
- 책상 카드 클릭 → agent.html?id=payroll 상세 페이지(작업 이력, 업로드, 결과 다운로드)

완료 후: 데모 작업을 실행해서 상태가 대기중→일하는중→검토필요→(승인)→완료→대기중으로 바뀌는지 확인하는 방법을 알려줘.
```

## [2] 단계 2 — 페이 (Payroll & 원천세)

```
2단계: Payroll 에이전트를 구현해줘.

[입력] 급여대장 엑셀 (사번, 성명, 마스킹 주민번호, 입사일, 기본급, 식대, 자가운전보조금, 상여, 부양가족수, 20세이하 자녀수)
       + 사업소득자/기타소득자 지급내역 시트

[처리]
1. 입력 검증: 필수값 누락, 숫자 형식, 중복 사번 → 오류 리포트
2. 비과세 구분 (식대·자가운전보조금 한도는 rules/payroll.yaml에서 읽기)
3. 4대보험 근로자·사업주 부담분 계산 (국민연금 기준소득월액 상·하한, 건강보험, 장기요양, 고용보험) — 요율은 rules/insurance.yaml
4. 근로소득 원천세: 근로소득 간이세액표를 rules/simple_tax_table.csv로 두고 조회 (샘플 구간만 넣고 전체표는 TODO로 표시) + 지방소득세
5. 사업소득(3.3%), 기타소득(필요경비 공제 후 세율 적용) 원천징수 계산
6. 원천징수이행상황신고서 형식으로 소득종류별 인원·총지급액·소득세·지방소득세 집계
7. 이상항목 플래그: 전월 대비 급여 30% 이상 변동, 최저임금 미달 의심, 국민연금 상한 해당자

[출력] 엑셀 1개 — 시트: 급여명세(개인별) / 4대보험 / 원천세 집계 / 이상항목 / 계산근거(적용 요율·기준연도)
[상태] 진행 중 "32명 중 n명 계산 중"으로 progress 업데이트, 완료 시 검토필요
[테스트] 월급 300만원·부양가족 1명 등 손계산 케이스 3개 이상

연말정산·퇴직소득은 이번 단계에서는 "추후 확장" 메뉴만 만들고 구현하지 마.
```

## [3] 단계 3 — 북키 (Bookkeeping & 결산)

```
3단계: BK 에이전트를 구현해줘.

[입력] 은행 거래내역 CSV, 법인카드 사용내역 CSV, 기존 계정과목표, 전기 말 잔액

[처리]
1. 분개 추천: 적요·거래처 키워드 규칙(rules/account_mapping.yaml)으로 계정과목 추천 + 신뢰도(높음/낮음).
   신뢰도 낮음은 "확인필요"로 표시 — AI가 확정하지 않음
2. 분개장 → 총계정원장 → 합계잔액시산표 생성, 차대 일치 검증
3. Reconciliation: 은행잔액 vs 장부 보통예금 잔액, 미결제 항목(시차) 목록, 원인불명 차이 별도 표시
4. 가지급금·가수금·미지급비용 등 주요 BS 계정 잔액 이상 플래그 (장기 미정리, 마이너스 잔액)
5. 월/분기/연 결산 체크리스트 자동 생성 (감가상각, 선급비용 상각, 미지급비용 계상, 외화환산 등) — 완료 체크 가능
6. 외부감사 PBC(요청자료) 리스트 템플릿 생성 및 준비상태 관리

[출력] 엑셀 — 분개장 / 시산표 / 은행 Reconciliation / BS 계정 검토 / 결산 체크리스트 / PBC 리스트
[테스트] 차대 불일치 데이터, 은행잔액 차이 데이터로 오류·검토필요 상태가 제대로 뜨는지
```

## [4] 단계 4 — 배트 (VAT)

```
4단계: VAT 에이전트를 구현해줘.

[입력] 매출 세금계산서 목록, 매입 세금계산서 목록(홈택스 다운로드 형식과 유사하게), 장부 매출·매입 데이터, 카드매입 내역

[처리]
1. 세금계산서 vs 장부 대사: 사업자번호+공급가액+작성일 기준 매칭 → 일치 / 금액차이 / 장부누락 / 세금계산서누락 4분류
2. 불공제 매입세액 후보 플래그: 접대비 관련, 비영업용 소형승용차 관련, 사업무관, 면세사업 관련 (판단 키워드는 rules/vat.yaml, 최종판단은 사람)
3. 부가세 신고서 요약: 과세표준, 매출세액, 매입세액(공제/불공제), 카드매입 공제분, 납부(환급)세액
4. 세금계산서 발행 관리: 미발행·지연발행 의심 매출 건 리스트, 가산세 위험 안내(세율은 rules에서)
5. 예정/확정 신고기한 D-day 표시

[출력] 엑셀 — 대사결과 / 불일치 상세 / 불공제 후보 / 신고서 요약 / 계산근거
```

## [5] 단계 5 — 코택 (법인세) + 매니저 (총괄)

```
5단계: Corporate Tax 에이전트와 Office Manager 에이전트를 구현해줘.

[코택]
1. 시산표(북키 결과물 재사용)를 입력받아 세무조정 체크리스트 생성: 접대비, 감가상각비, 퇴직급여충당금, 대손충당금, 기부금, 업무용승용차, 가지급금 인정이자 등 — 해당 계정 잔액과 함께 "검토 필요 여부" 표시
2. 접대비 한도 계산기 (기본한도·수입금액 기준 한도 요율은 rules/corptax.yaml, 중소기업 여부 선택)
3. 세무조사·외부감사 대응 요청자료 목록 템플릿과 준비상태 트래킹
